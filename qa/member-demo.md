# สมาชิกและเคส — local demo

เปิด http://127.0.0.1:8081/ แล้วกดปุ่ม "เข้าสู่ระบบ" มุมขวาบน

| บทบาท | Username | Password |
|---|---|---|
| สมาชิกสาธิต | demo_user | PlimoMemberDemo2026! |
| Admin สาธิต | demo_admin | PlimoAdminDemo2026! |

บน VPS สาธารณะ `demo_admin` ถูกล็อกเป็นค่าเริ่มต้น (รหัสอยู่ใน repo) เว้นแต่ตั้ง `DEMO_ADMIN_OPEN=true` ใน `.env` (เปิดไว้สำหรับสาธิตในชั้นเรียน ข้อมูลเป็นข้อมูลทดสอบ) บัญชี admin หลักคือ `ADMIN_USERNAME` / `ADMIN_PASSWORD` ใน `.env` ใช้ได้เสมอ

บัญชีเหล่านี้สร้างตามคำขอสำหรับ local demo ไม่ใช่บัญชีใช้งานจริง มีประวัติแชทตัวอย่าง 3 บทสนทนา และเคสตัวอย่าง 8 เคสที่กระจายหลายสถานะ ข้อความที่ seed ระบุว่าเป็นประวัติตัวอย่าง ไม่ใช่ผลทดสอบ AI จริง

หน้า Admin: http://127.0.0.1:8081/admin.html ต้องเข้าสู่ระบบด้วยบทบาท admin ก่อน API ตรวจสิทธิ์แยกจาก UI

สมาชิกเปิดประวัติของตัวเอง ส่งเคสจากบทสนทนาหรือกรอกใหม่ และดู timeline ได้ Admin ดูเฉพาะแชทที่แนบกับเคส นับเคสตามสถานะ และอัปเดตตามลำดับพร้อมหมายเหตุ เก็บผู้แก้ไขและเวลา

SQLite อยู่ใน Docker volume member-data แยกจาก Redis และ LightRAG ข้อความเก็บย้อนหลังได้เมื่อ Redis หมดอายุ ภาพตัวเครื่อง/หน้าจอ/สลิปของสมาชิกเก็บแบบส่วนตัว (R2 หรือดิสก์ ลบ EXIF แล้ว) ภาพบัตรและภาพไม่เกี่ยวข้องไม่เก็บ ไม่มีการ ingest ข้อมูลส่วนตัวเข้า RAG

Seed อีกครั้งได้ด้วย `docker compose exec api python seed_demo.py` จะไม่สร้างซ้ำหรือเขียนทับข้อมูลเดิม

ระบบสมาชิกและเคสใช้ backend Docker local ส่วน chatgpt.site เป็น static preview แสดงลิงก์ไป local เมื่อ backend ไม่พร้อม

## ถามเคสและอนุมัติราคา

ถาม `เคสของฉันถึงไหนแล้ว` หรือ `สถานะเคส PLM-00005` ในแชท สถานะอ่านสดจาก SQLite ตามเจ้าของบัญชี ไม่แคชคำตอบและไม่เรียก GPT

Admin เลือก `รออนุมัติราคา` พร้อมราคา สมาชิกเปิดงานซ่อมของฉันแล้วเลือกอนุมัติหรือปฏิเสธและกดยืนยัน การอนุมัติคงสถานะรอร้านเริ่มซ่อม การปฏิเสธกลับตรวจเช็ค สามารถส่งราคาใหม่ได้ ใบเสนอฉบับเก่ากดยืนยันไม่ได้

เคสตัวอย่าง PLM-00005 ได้อนุมัติใบเสนอ #1 ราคา 990 บาทระหว่างตรวจ UI แล้ว หากต้องการสาธิตการอนุมัติซ้ำ ให้ Admin ส่งใบเสนอใหม่ ระบบเก็บการตัดสินใจเดิมไว้
